# Phase 4 — PDF / .tex / Paste Onboarding

> **For Claude:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`.

**Goal:** Three onboarding paths for an existing resume:
- Upload PDF → text extraction → Claude maps content into Jake's template → saved as master.
- Upload `.tex` → save as master directly (assume it already conforms).
- Paste LaTeX → same as `.tex` upload.

After mapping, the master is run through `OnePageEnforcer` (in case the source overflows).

**Anchor:** design doc §1 "Onboard a resume".

**Scope/deviation:** Use lightweight `pypdf` text extraction instead of Marker (the design's preferred extractor). Marker pulls heavy ML deps that bloat the api image; for the walking-skeleton-style single-tenant app the text-extraction + Claude-mapping path is good enough, and the design doc already calls out a "fallback to raw text extraction" mode for Marker failures. This is that mode, applied as the default in Phase 4. Upgrading to Marker is left to a follow-up plan.

**Out of scope:** Multiple templates selection (we only have `jakes`); template selection UI; Marker; image-only PDFs (OCR).
